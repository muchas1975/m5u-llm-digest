新着ニュース

  • 512GB M5U の発注が始まった（10/28）: 最低 $22,299、16TB SSD にすると $29,799。納期は11月末〜12月初旬との報道あり。512GB は 36コアCPU/80コアGPU のみで、256GB からの追加は $11,500（https://www.techrepublic.com/article/news-apple-mac-studio-512gb-ram-price-specs/ 、納期は https://mezha.net/eng/news/39a0d4a9_apple_prices_512gb_mac/ ）。メモリアップの $15,500 は M3 Ultra 2025年当時の同ステップの 1GB あたり約3.9倍の単価（PCメモリ高騰に沿った水準）（https://www.techradar.com/pro/apple-will-now-sell-you-a-mac-studio-with-512gb-of-ram-but-itll-cost-you-as-much-as-a-good-sized-family-car ）
  • llama.cpp b12202（11/8）→ b12208: M5 Ultra 上で top-k を 20-45% 高速化する Metal 最適化（atomic ループを連続パスに変える）。コミットの支援クレジットに「GLM-5.3-Flash-GGUF (Mac Studio, M5 Ultra, 256GB)」の署名が付き、M5U で実際に動かしているコミュニティが llama.cpp 本体の改善に食い込んでいるのが分かる（https://github.com/ggml-org/llama.cpp/releases/ ）
  • llamaperf の件数は止まった模様: 前回「34件（as of 7 Nov）」の後、今日のスニペットも「34件・as of 8 Nov」のまま。ただしページを直接読むと古いキャッシュ（32件・as of 5 Nov）が返ってきたので、正確な件数は断定できない（https://llamaperf.com/gpu/m5-ultra-256gb ）

実行環境・事例

  • Claude Code の開発ワーカーにローカルLLMを混ぜる実案件検証（11/3、日本語）: Rails のマージ済み PR 18件を題材に、M5U 256GB（64コアGPU）で測定。結論は、Sonnet 単独が一番速く安い（16/18合格・199件/h・$0.36）、GLM-5.3-Flash 単独は同品質（16/18）だが13件/h で 1/15、「Claudeが仕様整理→ローカルが実装→Claudeがレビュー」の分業は費用2-4倍・処理量1/20で割に合わない。技術メモとして: mlx-vlm だと 3.8 tok/s だった GLM が oMLX+MTP で 69-73 tok/s（実行系で20倍差）、Claude Code 経由でも oMLX のプレフィックスキャッシュ命中率 98.9% で prefill は詰まない、GLM は「ターン数の使い切り」で落ちやすい（https://tchikuba.github.io/blog/2026/11/03/local-llm-on-mac-studio/ ）。注意点： macOS の動く壁紙（Aerial）がデコードサービスのメモリを10時間で104GBまで膨らませ、GLM のロードが落ちたという報告が記事内にある。静止画に変えると22MBに戻る。256GB 機ではモデルロード前に常駐プロセスの確認が要る（同上）
  • NetworkChuck の M5U vs M3U 実測リポジトリ（前回未報告）: 同一モデル・同一設定で、Qwen3.8 27B の 32K プロンプト読みが 388→1,526 tok/s（3.9倍）、生成 27.8→42.6（1.5倍）、初トークン 83.6秒→21.3秒。画像生成 FLUX.2 klein 4B が 7.00秒→1.77秒。「読みは4倍、書きは1.5倍」の構図を公式スペック根拠つきで整理したもの。Hermes agent を 27B で回して 89秒、というエージェント実測も載っている（https://github.com/theNetworkChuck/mac-studio-m5-ultra-local-ai ）
  • 1M コンテキストの個人実測（前回未報告）: DeepSeek-V4.1-Flash 自作 3-bit で、130K prefill 2,545 tok/s、1M prefill 1,998 tok/s（521秒）。会話再開時は prefix cache で 128K を0.8秒（従来53秒）。なお RTX PRO 6000 ×2 を並べると同じ 130K が 9,724 tok/s になる比較表付き（https://tacos8me.github.io/m5-ultra/ ）

向いているモデル

  • MiMo-V2.6-Flash が帯域比を示さない実例（llmcheck 更新）: M5U 80コアで 61.7 tok/s に対し、M3 Ultra の3実測は 55.1-59.4 tok/s で差は4-12%しか付かない（帯域比1.5倍に遠い）。この実測を機に llmcheck のインデックス1位は Qwen 3.6-35B-A3B に交代（https://llmcheck.net/blog/m5-ultra-vs-m3-ultra-vs-m5-max-local-llm/ ）
  • ボヘミアンシリコン（レンタル機）の6モデル表が同記事経由で読める： GPT-oss 20B 184 tok/s、Qwen3.5 9B 167、GPT-oss 120B 120、Gemma 4 31B 31（mlx-lm 0.32）（同上）
  • 512GB を検討する場合の参考： DeepSeek-V4.1-Flash の 3-bit（381GB）なら 512GB（実質409GB）に完全搭載可能、と vdf.ai のガイドが整理（https://vdf.ai/blog/mac-studio-m5-ultra-local-llm/ ）

ハーネス・ツール

  • oMLX 0.7.3 安定版（10/31）の中身（前回は 0.7.4.dev1 の話のみだったので整理）: DeepSeek V4.1 Flash に INT8 Activation Prefill を追加し、64K prefill が 2,882→3,507 tok/s（+22%）、195K で +29%。Engram prefetch で 128K が +15%。8リクエスト同時で KV キャッシュをその場更新に変え、M3 Ultra の 8ストリーム実測でメモリ -35%・decode +33%（https://newruntime.com/posts/omlx-0-7-3-speeds-up-deepseek-v4-fd0577/ ）
  • llama.cpp v0.9.0（11/4、不確か）: dev.to 記事が OCP FP8 量子化、複数シーケンス KV で効く flash_attn_ext_rows、Chatterbox TTS などの内容で報じているが、v0.9.0 タグは GitHub リリース一覧で確認できず（b12202/b12208 が先頭）。報道ベースとしておく（https://dev.to/madnessbrains_i/llamacpp-090-ships-chatterbox-tts-and-ocp-fp8-local-speech-still-dies-on-the-windows-capture-10n0 ）
  • LM Studio 本体は 0.4.28（10/31）が現行、と vdf.ai が整理。M5U 直結の実測数字は相変わらずなし（https://vdf.ai/blog/mac-studio-m5-ultra-local-llm/ ）

次に見るべき点: b12202/b12208 で入った M5U 固有の最適化が、GLM-5.3-Flash や DeepSeek のコミュニティ実測 tok/s に反映されるか。llamaperf の件数が34から動き出すかもあわせて。
