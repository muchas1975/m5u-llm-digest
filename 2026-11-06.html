何が新しかったか

  • 256GB で DeepSeek V4.1-Flash 552B をフルに載せて 1M トークン・コンテキスト、decode 92 tok/s の実測が出た（10/31）。
  • 日本語の実検証記事が 11/3 に公開：「Claude Code の開発ワーカーにローカルLLMを混ぜる」を実案件で測った結果、GLM-5.3-Flash が本命だが分業構成は割に合わない、という結論。
  • Apple 公式が MLX + RDMA 分散推論の使い方を公開（10/15）。LM Studio は 10/31 に 0.4.28。

新着ニュース

  • 552B が 256GB でフル実行： DeepSeek V4.1-Flash（552B・アクティブ16B、10/17 オープンソース版）を 3bit 量子化（重み約207GB、残り約49GB）で MLX に載せ、KVキャッシュ bf16・コンテキスト 1M で decode 92 tok/s、prefill 3883 tok/s、MTP／PLD 併用で最大 163 tok/s。条件は concurrency 1・greedy・3回の median（https://www.besthub.dev/articles/552b-deepseek-on-m5-ultra-256gb-3883-prefill-92-decode-tok-s-local-full-scale-llm-achieved-495dc311f584）
  • ※この数字はコミュニティのツイート画像がソースで、第三者の独立再現はまだ無い。「不確か」として扱う（同記事も明記）。
  • llamaperf の集計（11/6 更新）： M5 Ultra 256GB のレポートは 33 件に増加。最多で走られているのは DeepSeek V4.1 Flash 552B（3-bit）で median 73.4 tok/s・prefill 1010 tok/s（https://llamaperf.com/gpu/m5-ultra-256gb）
  • Apple 公式（10/15）: MLX v0.30.1 以降で Thunderbolt 5 経由 RDMA（jaccl）対応の分散推論を解説（https://machinelearning.apple.com/research/mlx-distributed-inference）
  • Bohemian Silicon（10/22）: 16 モデルを同時に 1 時間フル負荷 → 約98万トークン生成、100万トークンあたり 0.074 kWh。熱も速度も落ちず（https://bohemiansilicon.com/blog/mac-studio-m5-ultra-one-hour-ai-load-test/）

実行環境・事例

  • 日本語の実検証（11/3、tchikuba）: Rails の実案件 PR 18 件を Claude Code ハーネスで測定。GLM-5.3-Flash（oMLX + oQ4e + MTP、182GB）は 69〜73 tok/s、完走すれば Sonnet と同等の品質（採点者はモデル名を知らず A/S 評価）だが時間は 4〜15 倍、大きな課題では 3 回中 2 回がターン上限。Qwen3-Coder-Next は 110 tok/s と速いが自然言語の課題文で品質が崩れる（合格 50%）。「Claude が仕様整理 → ローカルが実装 → Claude がレビュー」の分業は、費用も速度も Claude 単独に負けた（指揮・レビューのトークンが本体の実装コストを上回る）。結論は「急がない小〜中の課題を夜間に流す補助レーン」（https://tchikuba.github.io/blog/2026/11/03/local-llm-on-mac-studio/）
  • 同記事の重要な発見： LLM のレビューは品質ゲートにならない——GLM 実装の欠陥を Opus が 3 件中 3 件見逃して approve。自動テストを必ず置くべき（同上）。
  • 256GB オーナー向けの注意（同記事）： macOS の「動く壁紙（Aerial）」が動画デコードの常駐プロセス（VTDecoderXPCService）を 10 時間で約 104GB まで膨らませ、モデルロードを強制終了させた。静止画に変えると 22MB に戻り増えも止まる。大型モデルを載せる前は footprint や top -o mem で常駐メモリを確認。
  • GPU の wired 上限： 既定のままで約 240GiB 使えるので、200GB 級のモデルも設定変更なしで載る。上限を引き上げない方が安全（同上）。
  • Apple 公式の分散推論（10/15）: 単体 M5 Ultra は M3 Ultra 比で TTFT 最大 4.6 倍（Neural Accelerator 効果）、decode 1.6 倍（1.2TB/s）。Muse Spark Open（816B・NVFP4・493GB）は 4 台テンソル並列で 36.7 tok/s。mlx_lm.server を OpenCode に接続する手順も掲載（https://machinelearning.apple.com/research/mlx-distributed-inference）

向いているモデル（256GB 実測）

  • DeepSeek V4.1 Flash 552B・3-bit（重み207GB）: 92 tok/s、prefill 3883 tok/s、1M コンテキスト（10/31 実測。※コミュニティ情報、未独立再現）（https://www.besthub.dev/articles/552b-deepseek-on-m5-ultra-256gb-3883-prefill-92-decode-tok-s-local-full-scale-llm-achieved-495dc311f584）
  • GLM-5.3 Flash（320B・アクティブ18B）: oMLX oQ4e + MTP で 80〜90 tok/s（llamaperf の複数レポート、一部は 61〜76 tok/s）（https://llamaperf.com/gpu/m5-ultra-256gb）
  • Qwen3.8 Flash-Next（125B・アクティブ6B）: oMLX Q6_K_XL で 141 tok/s。2 台クラスタ（Q6・Tensorfold）では decode 200 tok/s・prefill 8000 tok/s（同上）
  • Qwen3.5 122B・アクティブ10B: 4-bit で 74.7 tok/s（同上）
  • Qwen3.8 27B（dense）: MLX 4-bit で 47.6 tok/s（同上）
  • 傾向として、256GB の本命は「207GB 超の 550B 級を 3-bit で」「180GB 級の 300B 級を 4-bit で」の2レーン。dense 27B 級は余りを KV や並列に回す用途。

ハーネス・ツール

  • LM Studio 0.4.28（10/31）。0.4.27（10/29）は M5 世代 Metal runtime の互換性チェック修正・Neural Engine Prefill の設定追加。0.4.26（10/13）で llama.cpp runtime を 2.50.0（upstream b11337）に更新（https://lmstudio.ai/changelog/lmstudio）
  • 注意: LM Studio の llama.cpp runtime が M5 世代で Metal 4 の tensor API（Neural Accelerator）を有効化できておらず、GGUF の prefill が 2〜3 倍遅い問題が issue #2040 でまだ open。MLX 系ランタイムは影響なし。0.4.27 の修正で直ったかは不確か。prefill 重視なら MLX／oMLX 系が安全（https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/2040）
  • Ollama 0.40（9/25 リリース）: 対応アーキテクチャのモデルは Apple Silicon で MLX をデフォルト実行に（https://jacar.es/en/ollama-0-40-mlx-default-apple-silicon/）
  • oMLX が 256GB では最も人気のエンジン（llamaperf 33 件中 15 件が oMLX、MLX 7 件）。0.7.1 で GLM が +20〜30 tok/s、0.7.3rc1 まで出ている（https://llamaperf.com/gpu/m5-ultra-256gb）
  • MLX-Serve プラグイン（10/30）: DeepSeek 4.1 向けコミュニティ STQ カーネル対応が発表（10/31 記事が報道）（https://www.besthub.dev/articles/552b-deepseek-on-m5-ultra-256gb-3883-prefill-92-decode-tok-s-local-full-scale-llm-achieved-495dc311f584）
  • llama.cpp: b12100 pre-release（11/4）で -hf タグの量子化名マッチ修正など（https://newreleases.io/project/github/ggml-org/llama.cpp/release/b12100）
