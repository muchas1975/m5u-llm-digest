何が新しかったか

  • llamaperf の追試レポートが33件→34件に動き出し、DeepSeek 552B（3-bit）のメディアン 73.4 tok/s が公式数字として載った。
  • 件数以上に中身が増えていて、2台クラスタなら 200 tok/s、逆に 4-bit DeepSeek は1台だと 20-25 tok/s に落ちる、という両極の実測が読めた。
  • LM Studio と llama.cpp に小さな更新（どちらも M5U 直結の数字はまだなし）。

新着ニュース

  • llamaperf が 33→34 件に（as of 7 Nov）。前回「33 のまま」だった追試レポートがようやく +1。件数の伸びはまだ1日1件ペースだが、DeepSeek V4.1 Flash 552B・16B active の 3-bit で median 73.4 tok/s が集計として出た。エンジン内訳は oMLX 16件・MLX 7件・llama.cpp 3件など（https://llamaperf.com/gpu/m5-ultra-256gb）
  • llama.cpp b12191（11/7）: MoE キャッシュで逃した expert を CPU 側で計算する機能（--moe-cache-cpu-share）と、最適値を推測してくれる moe-cache-tune.py スクリプトが入った。256GB で MoE 大モデルのキャッシュが足りないときに効く仕組みだが、M5U での実測数字はまだ報告されていない（https://github.com/ggml-org/llama.cpp/releases）

実行環境・事例

（llamaperf のレポート一覧の中身は今回初めて確認できたもの。各レポートに日付表記はないので「34件の中の1つ」までの正確さ）

  • 2×M5U 256GB クラスタで 200 tok/s: Thunderbolt 5 ケーブル2本でつなぎ、Tensorfold の公式ガイド通りに DeepSeek 側がセットアップまで代行してくれたという報告。Qwen3.8 Flash-Next（Q6）で decode 200 tok/s・prefill 8,000 tok/s。同じクラスタの GLM-5.3-Flash は 50 tok/s で「遅すぎる」と不評。ハーネスは Hermes を使っていて「軽いハーネスなら速くなるか」と質問つき（https://llamaperf.com/gpu/m5-ultra-256gb/reports）
  • 4-bit DeepSeek は1台だと載りきらない: oQ4e だと MoE expert を 65% SSD に逃がす必要があり decode 20-25 tok/s・prefill 500 tok/s（メモリ使用量は最大 203.6GB）。「3-bit で 73-100 tok/s」より全然遅いので、256GB 単体の実用線は 3-bit 相当までという裏付けになった（同上）
  • GLM-5.3-Flash を llama.cpp で 61 tok/s: 内蔵 MTP ヘッドの確率的 draft（3トークン）を使った値で、MTP off だと 39.7 tok/s。262K コンテキストが全部入りで 15GiB 余る。ただし deep context に未マージの修正が必要という注意つき（同上）
  • M5U 256GB（prefill）+ M3 Ultra 512GB（decode）の分割構成: JACCL RDMA（TB5×2）で前段と後段を分け、35万トークン級の KV ハンドオフが 38ms。first token が 18.5秒（1台だと40秒相当の計算）。ただし「prefill 側に全モデルが必要なので、載るのは 256GB に収まるモデル限定」と考察つき（同上）
  • DeepSeek 552B Q4 + SSD Engram の動画（11/5）: 「M5U 256GB で Q4 を SSD Engram で、DGX Spark クラスタと比較」という動画が上がっている。ページが JS 動画で中身は確認できず不確か（https://divert.stream/watch/TCZtDI2K1nY）

向いているモデル

  • Qwen3.5 122B-A10B（4-bit）が 74.7 tok/s・prefill 2,710 tok/s: DeepSeek 552B 3-bit（73.4 tok/s）とほぼ同じ速度で、メモリ余裕は 72.3GB 使用と軽い。「73 tok/s 以上欲しいなら Qwen3.5 のほうが楽」という比較材料（https://llamaperf.com/gpu/m5-ultra-256gb）
  • Meta の Muse Spark Open（10/15、前回未報告）: 総 816B・42B active の MoE モデル。4-bit でも約 493GB なので 512GB 1台にも載らず、M5U 512GB 2台の tensor parallel で 25 tok/s、4台で 37 tok/s（Apple 公布の MLX ベンチ）。256GB 単体では動かないが、「M5U を複数台つなげばフロンティア級も動く」ことの公式裏付け（https://www.iclarified.com/102861/meta-releases-muse-spark-open-ai-optimized-for-mac-studio）

ハーネス・ツール

  • LM Studio Bionic 1.2.0（11/5）: 前回書いた oMLX エンジン搭載（1.1.10）の次。oMLX 0.1.0 エンジンと llama.cpp 2.67.0 拡張パックに更新。実測数字なし（https://lmstudio.ai/changelog）
  • oMLX は 0.7.4.dev1（11/4）のまま更新なし。前回の Prefill Accelerator が現時点で最新（https://github.com/jundot/omlx/releases）
